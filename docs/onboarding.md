# Skippable animal customization

The first-run experience has three optional segments: animal, wardrobe, and personality. Every segment can be skipped, the step navigation allows revisiting choices, and a prominent skip-customization action goes directly to the project prompt. Name and role have defaults. The final segment asks only what the user wants to work on, plus the existing pilot invite when required.

Six code-built Three.js voxel animals are available: fox, rabbit, cat, dog, otter, and frog. Outfits are hoodie, suit, polo, and casual shirt with pants. Hats are none, beanie, cap, and bucket hat; outfit color is configurable. A draggable preview uses the same model builder as the office scene. Species is cosmetic and does not assign a personality. NPCs also have animal appearances.

Appearance uses allowlisted fields in the server-validated profile and persists in the existing session checkpoint. Older sessions without appearance fields get a fox in a hoodie. Invalid appearance options receive safe defaults. Customization during an active workday and cross-session saved profiles are deferred.

Known facts, constraints, open questions, and a separate outcome field are removed from setup. These can emerge through the working brief and conversation. The first guidance prompt acknowledges the project and starts bounded exploration unless a missing human decision materially blocks it; there is no forced confirmation gate. Existing optional backend context fields remain supported for compatibility. Personal notes remain private to the agent context rules.

Validation: 36 automated tests pass, including every species/outfit/hat combination in session snapshots, invalid appearance fallback, and no mandatory demo confirmation. A complete local demo workday passed. Browser inspection verified fox, frog, and otter previews, rabbit outfit/hat/color selection, optional personality entry, skipping, project-only entry, and avatar persistence after joining and refreshing. The production build passes. Deployed September 16, 2026; hosted browser checks confirmed the new flow and invite field. A live seven-call steering test verified saved otter/polo/cap appearance, a correction, a human-context pause with no autonomous calls, supplied context, brief updates, and report export; the test office was deleted.

A live regression exposed the model saying it would wait while marking itself ready to continue. New user messages now have a separate budgeted decision check before drafting; a blocking result overrides the drafting response and stops the scheduler. This adds one inference call per user message, within the existing call limit. It is model interpretation rather than a guarantee for every phrasing; regression tests cover enforcing its result, and live validation covers an explicit customer-segment decision. Initial review and automatic synthesis do not incur this extra message-routing call.
